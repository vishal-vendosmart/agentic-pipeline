# Zernio Content Scheduling - Bug Fixes

## Date: 2026-05-22

## Bug 1: Content Concatenation in LinkedIn Posts

**Problem**: LinkedIn posts contained all 3 platform versions (LinkedIn + X Personal + X WeFab) with `### X (@...)` headers.

**Root Cause**: The `extractContent` function in `zernio-schedule-all.mjs` only stopped at `---` between topics, not between sections within a topic.

```javascript
// BROKEN
if (line.startsWith('### X (@wefabdotAI)') && sectionName === 'X (@VishalIPatil)') { 
  inSection = false; 
  continue; 
}
// This only stopped X Personal extraction, not LinkedIn!
```

**Fix**: Stop at ANY `###` section header when inside a section.

```javascript
// FIXED
if (line.startsWith('### ') && inSection) { 
  inSection = false; 
  continue; 
}
```

## Bug 2: Formatting Stripped (No Paragraph Breaks)

**Problem**: LinkedIn posts were walls of text with no blank lines between paragraphs.

**Root Cause**: `line.trim()` filtered out blank lines.

```javascript
// BROKEN
if (inSection && line.trim()) content.push(line);
// This skips blank lines, removing paragraph breaks!
```

**Fix**: Don't strip blank lines during extraction.

```javascript
// FIXED
if (inSection) content.push(line);
// Blank lines are preserved as paragraph breaks
```

## Solution: Separate Files Per Platform

Instead of parsing sections from a combined file, we now have:
- `content/topics/topic01-linkedin-may22.md`
- `content/topics/topic01-xpersonal-may22.md`
- `content/topics/topic01-xwefab-may22.md`

**Benefits**:
1. Zero parsing risk
2. Clear separation of concerns
3. Easy editing per platform
4. Formatting preserved naturally

## Impact
- 2 published posts went out with bad content (May 21, May 22)
- 29 scheduled posts were deleted and re-created clean
- 87 posts now scheduled correctly (May 24 - Jun 20)

## Prevention
- Always use separate files per platform
- Never parse sections from combined content
- Preserve blank lines as paragraph breaks
- Test content extraction before bulk scheduling
